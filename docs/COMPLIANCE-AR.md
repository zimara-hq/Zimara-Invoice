# مصفوفة الامتثال

ربط كل متطلب نظامي بمكان تطبيقه في الكود وحالته الحالية. المرجع الأساسي: الدليل التفصيلي للفوترة الإلكترونية (هيئة الزكاة والضريبة والجمارك)، ونظام ضريبة القيمة المضافة ولائحته، ونظام حماية البيانات الشخصية.

**الحالات:** «مطبّق ومختبَر» يعني فيه اختبار آلي يثبته. «مطبّق» يعني مكتوب ومجرّب يدوياً. «يحتاج تحقق» يعني مكتوب حسب المواصفات لكنه ما انجرب على خوادم الهيئة. «غير موجود» يعني ما انبنى للحين.

## الفوترة الإلكترونية (المرحلة الثانية)

| المتطلب | التطبيق | الحالة |
|---|---|---|
| صيغة XML بمعيار UBL 2.1 | `src/lib/zatca/xml.ts` | مطبّق ومختبَر (يتحقق من صحة الصيغة) |
| UUID لكل مستند | `invoicing.ts` | مطبّق ومختبَر |
| عداد فواتير (ICV) ما ينعاد ضبطه | جدول `egs_units` ومعه قيد في قاعدة البيانات يرفض أي نقص | مطبّق ومختبَر |
| سلسلة بصمات (PIH) وسلسلة وحدة لكل وحدة إصدار | قفل `FOR UPDATE` داخل معاملة واحدة | مطبّق ومختبَر (حتى مع 6 إصدارات في نفس اللحظة) |
| ختم التشفير ECDSA على secp256k1 | `crypto.ts` و`sign.ts` | مطبّق ومختبَر |
| رمز QR بالحقول 1 إلى 9 | `sign.ts` | مطبّق ومختبَر |
| توقيع XAdES (SignedProperties وبصمة الشهادة) | `sign.ts` | **يحتاج تحقق** على بوابة المطورين: `npm run zatca:sandbox-check` |
| طلب الشهادة CSR بحقول الهيئة | `x509.ts` | مطبّق ومختبَر (OpenSSL يتحقق منه) |
| الحصول على شهادة الامتثال وشهادة الإنتاج | `fatoora.ts` و`onboarding.ts` | **يحتاج تحقق** على خوادم الهيئة |
| فحوصات الامتثال على 6 أنواع مستندات | `onboarding.ts` | مطبّق ومختبَر محلياً، ويحتاج تحقق مع الهيئة |
| الاعتماد (Clearance) قبل تسليم الفاتورة الضريبية | `submitDocument` | مطبّق، ويحتاج تحقق |
| المشاركة (Reporting) للمبسطة خلال 24 ساعة، مع إعادة محاولة | `submitDocument` و`/api/cron/zatca` | مطبّق، ويحتاج تحقق |
| حفظ النسخة المعتمدة من الهيئة | العمود `cleared_xml` | مطبّق |
| منع حذف أو تعديل المستند الصادر | قيد في قاعدة البيانات (`zimara_guard_documents`) ومنع TRUNCATE | مطبّق ومختبَر |
| الإلغاء فقط بإشعار دائن يشير للفاتورة الأصلية (المادة 54) | المدقق، و`BillingReference`، و`ref_document_id` | مطبّق ومختبَر |
| منع تغيير وقت الإصدار | الوقت من ساعة الخادم بتوقيت الرياض فقط، وما فيه حقل له في الواجهة | مطبّق |
| سجل نشاط ما يقبل التعديل | جدول `audit_log` ومعه قيد append-only | مطبّق ومختبَر |
| المفتاح الخاص ما يمكن عرضه أو نسخه | تشفير AES-256-GCM وما يظهر في أي واجهة | مطبّق ومختبَر. في الإنتاج يُفضّل KMS أو HSM |
| تسجيل دخول إلزامي وصلاحيات حسب الدور | الجلسات، و`requireCtx`، والأدوار (مالك، مدير، محاسب، عرض فقط) | مطبّق |
| منع كلمات المرور الافتراضية | كل مستخدم يختار كلمة مروره، وتنفحص قوتها | مطبّق |
| بيانات الفاتورة بالعربي | الواجهة والمستند بالعربي، مع عناوين إنجليزية مساعدة | مطبّق |
| PDF/A-3 مع XML مضمّن | — | **غير موجود** (الطباعة وتنزيل XML متاحين). إلزامي فقط إذا أرسلت الفاتورة بصيغة PDF |
| الأرشفة 6 سنوات وإمكانية التصدير للأرشفة الخارجية | ما فيه حذف أبداً، وتنزيل XML بتسمية الهيئة (الرقم الضريبي + الوقت + الرقم) | مطبّق. يحتاج سياسة نسخ احتياطي في الاستضافة |
| وصول الهيئة للبيانات عند الطلب | التصدير وتنزيل XML | مطبّق |

## التجارة الإلكترونية وحماية المستهلك

| المتطلب | التطبيق | الحالة |
|---|---|---|
| عرض الاسم والسجل وبيانات التواصل | أسفل الموقع من متغيرات `COMPANY_*` | مطبّق، وينتظر إصدار السجل |
| الأسعار واضحة مع بيان الضريبة | صفحة الأسعار: «قبل ضريبة القيمة المضافة 15%» | مطبّق |

| تذكير قبل التجديد التلقائي | مذكور في الشروط | يحتاج تطبيق مع بوابة الدفع |

## الأشياء الباقية قبل الإطلاق التجاري

1. تشغيل `npm run zatca:sandbox-check` وتعديل التوقيع حسب رد الهيئة إذا لزم.
2. بوابة دفع مرخصة من البنك المركزي السعودي، وإصدار فواتير الاشتراك.
3. ملف PDF/A-3 للفاتورة.
4. دعوة أعضاء الفريق وإدارة صلاحياتهم من الواجهة (الجداول جاهزة).
5. التحقق الثنائي (2FA) للمدراء.
6. مراجعة قانونية وفحص اختراق مستقل.
